# mew_companion — MVP 계획서 (운영자 1인 사용)

> 작성 2026-11-13 · Claude. 옛 계획 `mew_companion_plan.md`(Gemini 작성)를 대체한다 — 그 문서의 데이터 구조 서술은 실제와 달라 쓰지 않는다.
> **범위 = 운영자 본인 PC 에서만 쓰는 MVP.** 팬 배포(Store · 서명 · 저작물 근거)는 MVP 뒤에 따로 정한다.
> 「확인 필요」 표시는 아직 실측 · 원문 확인을 하지 않은 것이다.

---

## 1. 무엇을 만드나

바탕화면(다른 창 **뒤**)에 뮤타입 동물 캐릭터 5마리가 산다. 백그라운드에서 팬 사이트와 같은 데이터를 읽어

- **방송이 시작되면** 윈도우 토스트 알림을 띄우고, 해당 캐릭터가 반응한다.
- **캐릭터를 누르면** 그 멤버의 트윗(번역)을 작은 패널로 보여준다.
- **새 번역 트윗이 생기면** 토스트를 띄운다.

### 넣지 않는 것 (운영자 확정)
- 소식(`notices.json`) · 행사 배너(`banners.json`)
- 팬 배포용 작업(설치 패키지 · 서명 · Store) — MVP 뒤

## 2. 데이터 — 백엔드는 건드리지 않는다

웹 프론트와 똑같이 공개 JSON 을 읽기만 한다. 서버 · 비밀 키 · 쓰기 경로가 늘지 않는다.

| 파일 | 주소 | 쓰는 필드 |
|---|---|---|
| preview | `https://raw.githubusercontent.com/sbb2002/mewtype-scheduler-data/data/preview.json` | `channel_order` · `channels.{key}.name_ko` · `items[]` 의 `id` `state` `channel_key` `collab_with` `title` `title_ko` `url` `scheduled_start` |
| tweets | `https://raw.githubusercontent.com/sbb2002/mewtype-scheduler-data/data/tweets.json` | `tweets.{key}[]` 의 `id` `text_ko` `url` `expires_at` `reply_to_id` |

- 스키마 정본 = mewtype-scheduler `docs/SPEC.md` 계약 A(preview) · 계약 I(tweets). 위젯을 만들면 SPEC 에 「위젯도 이 스키마를 읽는다」를 한 줄 적어 스키마 변경 때 놓치지 않게 한다.
- 폴링 주기 = 웹과 같은 **75초**(`src/frontend/js/config.js` `POLL_MS`).
- 멤버 이름 · 순서는 실행 중 `preview.json` 에서 읽는다(빌드에 박지 않음).
- 시각은 전부 UTC 로 저장돼 있다 → 표시할 때 KST 로 바꾼다(웹 `time.js` 와 같은 규칙).
- **알림 지연**: 백엔드 확인 주기(예정 20분 전부터 3분 간격) + raw CDN 캐시(최대 약 5분) + 폴링 75초 → 방송 시작 뒤 수 분 늦을 수 있다. 웹 화면도 같다.

## 3. 알림 규칙 (순수 함수 하나 — `이전 상태 + 새 JSON → 알림 목록`)

| 알림 | 판정 | 토스트 내용 · 누르면 |
|---|---|---|
| 방송 시작 | 방송(`items[].id`)이 처음으로 `state == "live"` | 「[name_ko] 방송 시작」 + `title_ko`(없으면 `title`) → `url` 열기 |
| 새 트윗 | 처음 보는 트윗 `id` 이고 `text_ko` 가 있다 | `text_ko` 앞부분 → 트윗 `url` 열기 |
| 번역 늦은 트윗 | 처음 볼 때 `text_ko` 가 비어 있던 글에 번역이 들어왔다 | 위와 같음(이때 한 번만) |

- **번역 없는 트윗은 토스트를 띄우지 않는다**(운영자 확정). 번역이 오기 전에 `expires_at` 이 지나면 끝까지 안 띄운다.
- 대상 멤버 = 주 레인 `channel_key` ∪ 합동 `collab_with`. 합동이면 참여 캐릭터 모두 반응한다.
- **첫 실행 · 재시작**: 지금 데이터를 전부 「본 것」으로 기록만 하고 알리지 않는다(번역 대기 글 포함) — *Claude 제안, 운영자 확인 필요*.
- 「본 것」 기록 = `%APPDATA%\mew_companion\state.json`(본 방송 id · 본 트윗 id · 번역 대기 id).
- 네트워크 실패는 조용히 넘기고 다음 주기에 다시. 절전에서 깨어난 뒤 옛 알림이 몰려 뜨지 않게 「본 것」 기준으로만 판정한다.
- **확인 필요(운영자 결정)**: `assumed_live`(영상 없이 예정 시각이 지나 「방송 중(추정)」인 예고)도 방송 시작으로 알릴지. 초안은 **알리지 않음**(`state == "live"` 만).

## 4. 캐릭터 — 창 뒤 바탕화면에서만

### 4-1. 창 배치 (운영자 확정: 다른 창 뒤, 바탕화면이 보일 때만)
- 캐릭터마다 **작은 투명 창 1개**. 화면 전체 덮개보다 가볍고, 투명 픽셀은 클릭이 통과한다.
  그리기 = Win32 `UpdateLayeredWindow`(픽셀 단위 투명 창) + `tiny-skia`(부위 회전 · 확대 합성).
- **방식 A (MVP 채택)** — 일반 창을 z 순서 맨 아래(`HWND_BOTTOM`)에 고정하고, 다른 창이 올라와도 계속 맨 아래로 되돌린다. 작업표시줄에 안 보이게(`WS_EX_TOOLWINDOW`). 바탕화면 아이콘 위에 그려지지만 클릭이 된다.
- 방식 B (예비) — 바탕화면 배경 층(WorkerW)에 붙이기. 아이콘 뒤에 그려져 진짜 배경처럼 보이지만, 아이콘 층이 클릭을 가로채 캐릭터 클릭이 안 된다(별도 마우스 가로채기 필요). MVP 에선 안 쓴다.
- **확인 필요(Phase 0)**: 방식 A 창이 `Win+D`(바탕화면 보기) 때 같이 숨는지. 숨으면 「바탕화면 보기」로 캐릭터를 볼 수 없으니 대안을 찾는다.

### 4-2. 움직임
- **유노**: 부위 그림이 `main` 에 있다 — `src/frontend/assets/birthday/yuno/`(body · head_open/closed/flat · ear_l/r · arm_l/r · tail · headset, 각 약 170~380px).
  웹의 완성된 움직임은 생일 장면의 **DJ 연주**라, **걷기는 새로 만든다**. 다리 부위가 없으므로 「몸 위아래 흔들림 + 귀 · 꼬리 흔들림 + 눈 깜빡임(head_open ↔ closed) + 좌우 이동(좌우 반전)」으로 시작.
  동선 = 작업 영역(작업표시줄 제외) 아랫선을 따라 걷기 · 멈춤 · 쉬기 반복. 주 모니터만.
- **나머지 4명(아라레 · 노노카 · 리츠 · 미야코)**: **멈춘 상태**로 자리만 지킨다(운영자 확정). 움직임은 완성되는 대로 추가.
- 크기 = 화면에서 약 100~140px(원본을 줄여 쓴다).

### 4-3. 그림 출처 · 확인 필요
- 5명 부위 그림 · 조립 정보 = 브랜치 `easteregg/birthday-skin` 의 `easteregg/birthday/assets5/`(`*_body` · `*_head_*` · `*_ear_*` · `*_arm_*` · `rigs*.json` · `*_assembled_preview.png`).
- **확인 필요**: 부위마다 여러 라운드(`_round10` · `_round12` · `_round14` · `_pre_r11` …)가 섞여 있어 **어느 것이 최종인지** 아직 모른다. 그 브랜치 `HANDOFF.md` · `docs/BIRTHDAY_SKIN.md` 와 최신 `birthday_bg_v16.html` 이 실제로 읽는 파일로 확정한다.
  (참고: `HANDOFF.md` 14행은 PNG · WebP 가 zip 에만 있다고 적었지만 지금 브랜치에는 들어 있다 — 그 뒤 추가된 것으로 보이며 확인 필요.)
- 이 그림은 **공식 캐릭터를 참고해 AI 가 그린 팬 제작물**이다. MVP 는 본인 PC 전용이라 문제 되지 않지만, 앱 정보 창에 「비공식 팬 제작 · AI 생성 일러스트 · 공식과 무관」을 둔다(`docs/BIRTHDAY_SKIN.md` §7 과 같은 취지).

### 4-4. 상호작용
- **캐릭터 클릭** → 그 멤버 패널:
  - 방송 중이면 맨 위에 「방송 보러 가기」(→ `url`).
  - 아래에 트윗 목록 — 웹과 같이 `expires_at` 이 안 지난 글만, `text_ko` 없으면 「번역 준비 중…」, 누르면 X 로.
- **방송 시작** → 토스트 + 캐릭터 머리 위 LIVE 표시(방송이 끝나면 사라짐).
- **안 읽은 새 트윗** → 캐릭터 위 작은 점. 패널을 열면 지운다.

### 4-5. 자원
- 걸을 때만 15~20fps 로 그리고, 멈추면 다시 그리지 않는다. 전체 화면 앱 사용 중 · 화면 잠금 중엔 멈춘다.
- 목표 = 평소 CPU 거의 0, 걸을 때 소량. 메모리는 Phase 0 에서 실측해 목표를 정한다(옛 계획의 「15MB」는 근거 없는 수치).

## 5. 구성

```
mew_companion/                 (rust-examples 아래, mewtype-scheduler 저장소 밖)
├─ Cargo.toml
├─ assets/                     # 유노 부위 · 4명 정지 그림 · 멤버 아이콘(토스트용, member_icons 40×40)
└─ src/
   ├─ main.rs                  # 시작 · 트레이 · 스레드 연결
   ├─ poll.rs                  # 75초 폴링(ureq, 스레드 1개) — tokio 불필요
   ├─ model.rs                 # preview · tweets 역직렬화(serde) — 쓰는 필드만
   ├─ diff.rs                  # 알림 판정 순수 함수 + 단위 시험(fixtures 사용)
   ├─ state.rs                 # %APPDATA% 「본 것」 기록
   ├─ toast.rs                 # 윈도우 토스트 · 누르면 주소 열기
   ├─ critter/                 # 캐릭터 창 · 부위 합성 · 걷기 · 클릭
   └─ panel.rs                 # 멤버 패널(트윗 · 방송 보러 가기)
```

- **폰트**: 번역문은 한국어, 방송 제목 원문은 일본어 → 실행 시 `C:\Windows\Fonts` 의 맑은 고딕 · Yu Gothic 을 읽는다(exe 에 넣지 않음).
- **패널 UI**: 테두리 있는 작은 일반 창. 구현 수단(egui 등)은 Phase 2 에서 메모리 실측 후 정한다.
- **트레이 메뉴**: 알림 켜기/끄기(방송 · 트윗) · 시작 프로그램 등록(`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`) · 종료.
- **시험 데이터**: mewtype-scheduler `fixtures/preview.sample.json` · `fixtures/tweets.sample.json`.
- **개발 환경**: 이 PC 의 bash 에서 `cargo` 를 못 찾았다 — Rust 설치 · PATH 확인 필요.
